# Architecture Decision Records

ADR — короткие записи о значимых архитектурных решениях: **что** решили, **почему**, какие варианты отклонили и какую цену за это платим. Не журнал изменений и не туториал — решение, зафиксированное вместе с контекстом, в котором оно принималось, чтобы через полгода (или в новой сессии с ассистентом) не переоткрывать и не переспорить то, что уже обсудили и закрыли.

## Зачем это отдельно от `CLAUDE.md`

`CLAUDE.md` (в корне репозитория) — гид по **текущему состоянию**: как всё устроено сейчас, какими командами пользоваться. Он должен оставаться компактным и не обрастать историей.

ADR — про **историю решений**: почему устроено именно так, а не иначе, что рассматривали и отвергли. `CLAUDE.md` отвечает на вопрос «как это работает», ADR — на вопрос «почему это работает именно так». Правило записи этого разделения — [ADR-0001](0001-claude-md-and-adr-process.md).

## Когда писать ADR

Пишем, если решение отвечает хотя бы одному:
- меняет границу между модулями/контекстами (`Person`/`Billing`/`Core`/бандлы) или правило зависимостей между ними;
- выбирает технологию/библиотеку/паттерн там, где был реальный выбор (не единственный очевидный вариант);
- сознательно отклоняет более простой или более строгий вариант ради конкретной причины (цена/срок/риск);
- решение обсуждалось/спорили о нём — есть контраргументы, которые стоит сохранить, а не просто зафиксировать финальный код.

Не пишем ADR на:
- багфиксы и рефакторинги без изменения архитектурных правил — это `docs/refactoring-plan.md` или просто commit-сообщение;
- решения, у которых по сути не было альтернативы (например, «использовать Doctrine, раз это Symfony-проект на Doctrine»).

## Формат

Один файл — одно решение, номер не переиспользуется даже если статус решения изменился. Шаблон — [`template.md`](template.md).

- Имя файла: `NNNN-краткое-название-в-kebab-case.md`, `NNNN` — 4 цифры, следующий по порядку номер.
- Секции: Статус, Дата, Контекст, Решение, Последствия, Отклонённые варианты, Ссылки — см. шаблон.
- Статусы жизненного цикла:
  - 🟡 **Предложено** (Proposed) — обсуждается, ещё не решено окончательно.
  - ✅ **Принято** (Accepted) — действует.
  - ⏸️ **Отложено** (Deferred) — решение принято, но реализация сознательно отложена (см. пример в `docs/refactoring-plan.md` про логирование).
  - ❌ **Отклонено** (Rejected) — рассмотрели и не стали делать.
  - 🔄 **Заменено ADR-XXXX** (Superseded) — решение устарело, актуальная версия в другом ADR.
- ADR **не редактируется задним числом** при смене решения — меняется только строка статуса (с указанием, чем заменено), а новое решение оформляется новым файлом со ссылкой на предыдущий.
