# PUT/PATCH музыканта падают с 500, если у музыканта есть договор

**Статус:** 🟡 В работе (не начато) \
**Начато:** 2026-09-27 \
**Обновлено:** 2026-09-27

## Цель

Найдено на архитектурном ревью 2026-09-27. `PUT` и `PATCH /api/person/v1/musician/{id}` возвращают Doctrine-сущность `Musician`, а не выходной DTO. Сериализатор идёт `Musician::getContracts()` → `Contract::getMusician()` и падает с `CircularReferenceException`, если у музыканта есть хотя бы один договор. Воспроизведено на сериализаторе приложения в контейнере. Заодно presentation-слой отдаёт наружу доменную сущность — нарушение слоёв.

## План

1. `Person/Presentation/Http/Rest/Musician/Update/V1/{PutMusicianController,PatchMusicianController}.php` — внедрить `MusicianDtoFactory`, возвращать `MusicianDto` (`createFromMusician()`), как `GetMusicianByIdController`. Убрать импорт `Musician`.
2. Проверить: `lint:container`, `codecept run Unit`; вручную — музыкант с договором, `PUT` и `PATCH` отдают 200 с договором в ответе.

Исправление уже проверялось 2026-09-27 (на тестовой БД в откатываемой транзакции оба контроллера отдали `MusicianDto` с договором) и было откачено по решению пользователя — делать позже.
