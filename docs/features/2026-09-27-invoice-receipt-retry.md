# Проверка оплаты счетов: чек ОФД без повторной отправки

## Цель

Найдено на архитектурном ревью 2026-09-27. `Billing/Application/UseCase/CheckInvoicesPaidUseCase` для каждого счёта: проверяет оплату в эквайринге → `Invoice::paid()` + `flush()` → отправляет чек в ОФД. Проблемы:

- Если ОФД упал, счёт уже сохранён оплаченным (`PAID`), чека нет, и повторно он не отправится: `getReceived()` выбирает только `RECEIVED_BY_ACQUIRE`, а признака «чек отправлен» у `Invoice` нет.
- Любая ошибка по одному счёту выбрасывает `InvoiceManageException` и прерывает обработку всех остальных.
- Результат `sendReceipt()` (хеш чека) пишется в `$receipt` и не используется.

В коде помечено `//TODO возможны ошибки, требуется повторная отправка`.

## План

1. **Запоминать факт отправки чека в `Invoice`** — поле с хешем чека из ОФД (сейчас выбрасывается) и метод вроде `Invoice::receiptSent(string $receiptHash)`. Миграция на новую колонку. Счёт «оплачен, чека нет» = `PAID` без хеша.
2. **Разделить оплату и чек** (SRP): `CheckInvoicesPaidUseCase` только фиксирует оплату; отправка чеков — отдельный юзкейс по счетам «оплачен, чека нет» и своя консольная команда (`billing:invoice:send_receipt` по конвенции `<контекст>:<сущность>:<действие>`). Повторный запуск тогда сам дошлёт упавшие чеки — повтор без отдельной очереди.
3. **Ошибка одного счёта не прерывает пачку** — в обоих юзкейсах ловить ошибку внутри цикла, считать неудачные и продолжать; итог вернуть в команду. Писать ошибку в лог — после [логирования](2026-09-08-logging.md).
4. Добавить в `InvoiceRepositoryInterface` выборку «оплачен, чека нет».
5. Тесты: юзкейсы зависят от `final`-клиентов, замокать их нельзя (см. находку 4 в [`2026-09-27-layer-violations.md`](2026-09-27-layer-violations.md)) — либо Functional-тест на заглушках бандлов, либо сначала решить вопрос с интерфейсами клиентов.
