# Закрытие записей дневника и актуализация индекса

**Статус:** ✅ Готово \
**Начато:** 2026-09-27 \
**Обновлено:** 2026-09-27 \
**Ветка:** `feature/feature-log-closing`

## Цель

Записи в `docs/features/` не закрываются (статус не меняется на ✅/⏸️/❌), а индекс в `docs/features/README.md` расходится со статусами в файлах (пример на момент начала: `2026-09-16-markdown-changelog.md` — ✅, в индексе — 🟡). Причина: в рабочем процессе `CLAUDE.md` нет момента закрытия записи, а ✅ означает «смёржено» — событие вне сессии ассистента. Цель — чтобы закрытие происходило в определённые моменты, решение о закрытии принимал пользователь, а механика и сверка индекса выполнялись автоматически.

## План

1. Правило в `CLAUDE.md`: моменты закрытия — перед push/PR спросить пользователя, закрывать ли запись; в начале работы с `docs/features/` сверить открытые записи со смёрженными ветками.
2. Поле **«Ветка»** в шаблоне — чтобы связать запись со смёрженной веткой (по merge-коммитам `Merge pull request #N from <owner>/<ветка>`).
3. Скрипт `.claude/hooks/features-check.sh`:
   - `index` — сверка статусов индекса с файлами, наличие каждого файла в индексе;
   - `merged` — открытые (🟡/⏸️) записи, чья ветка уже влита в `master`.
4. Хуки в `.claude/settings.json`: `PreToolUse` на `git commit` — блокировать при расхождении индекса; `PreToolUse` на `git push` — напоминание спросить о закрытии; `SessionStart` — список записей со смёрженной веткой.
5. Правила в `docs/features/README.md`: когда закрывается запись, поле «Ветка», проверка хуком.
6. Исправить текущее расхождение индекса.

## Сделано

- `CLAUDE.md`, пункты 6–9 рабочего процесса: поле «Ветка», вопрос о закрытии перед `git push`, закрытие записей со смёрженной веткой по сигналу хука, синхронность статуса файла и индекса.
- `.claude/hooks/features-check.sh` (режимы `index`, `merged`, `pre-bash`, `session-start`) и хуки `PreToolUse` (Bash) и `SessionStart` в `.claude/settings.json`. Режимы проверены вручную на синтетическом JSON и временных расхождениях.
- `docs/features/template.md` — поле «Ветка»; `docs/features/README.md` — поле «Ветка», когда ставится ✅, описание проверок и их ограничение (squash-merge не распознаётся).
- Индекс: `markdown-changelog` приведён к ✅, как в файле.
- Разовая сверка старых записей: закрыта [`2026-09-08-minor-findings.md`](2026-09-08-minor-findings.md) — её ветка `feature/strict-return-types` смёржена в PR #5.
- Проверено в сессии: хук на `git commit` срабатывает. Известная неточность: напоминание перед push реагирует и на текст «git push» внутри сообщения коммита — ложное напоминание, на коммит не влияет.

## Не стали делать

- Хук на `gh pr create` (из первоначального обсуждения) — `gh` на машине не установлен, PR создаются не из сессии ассистента; момент «перед PR» заменён на `git push`.
- Поле «Ветка» в старых записях не проставлялось — у открытых записей ветки ещё нет или она уже смёржена; сверка старых записей сделана вручную один раз.
